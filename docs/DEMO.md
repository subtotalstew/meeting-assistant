# Сценарий демонстрации

Пошаговый прогон под защиту. Закрывает все пункты раздела 22 ТЗ: загрузка,
создание задачи, статус, транскрипция, выжимка, поиск, получение по идентификатору,
обработка ошибки и повтор.

Все команды работают в тестовом режиме: реальные Speech API и GigaChat не нужны.

## Подготовка (один раз, до выступления)

```powershell
docker compose up -d --wait          # PostgreSQL 16
go build -trimpath -o bin/ma.exe ./cmd/meeting-assistant
$env:LOG_FORMAT = "text"             # логи в stderr, читаемо на проекторе
```

```bash
# то же самое в bash
docker compose up -d --wait
go build -trimpath -o bin/meeting-assistant ./cmd/meeting-assistant
export LOG_FORMAT=text
```

Подготовить файлы:

```powershell
echo "аудиозапись встречи" > sprint-review.ogg
echo "битая запись" > fail-meeting.ogg
```

## 1. Регистрация

```console
$ ma.exe start --user alice
пользователь alice зарегистрирован
идентификатор: 01a1bb3c-9496-7aab-b4c0-4bb292ed8d93
```

Что сказать: в CLI регистрация автоматическая при первом обращении с новым
`--user`; `start` нужен, чтобы показать идентификатор и совпасть со сценарием
мессенджеров.

## 2. Загрузка и создание задачи

```console
$ ma.exe load sprint-review.ogg --user alice
встреча создана: 01a1bb3c-9561-7bdd-96bd-3e200d99f529
файл: sprint-review.ogg
статус: completed
транскрипция: meeting-assistant get 01a1bb3c-... --user alice
выжимка:     meeting-assistant summary 01a1bb3c-... --user alice
```

Что сказать: встреча и задача создаются одной транзакцией, задача уходит в очередь,
обработку выполняет пул воркеров этого же процесса. `--no-wait` оставит задачу
в очереди для режима `serve`.

## 3. Статус обработки

```console
$ ma.exe status 01a1bb3c-9561-7bdd-96bd-3e200d99f529 --user alice
встреча:      01a1bb3c-9561-7bdd-96bd-3e200d99f529
название:     sprint-review
статус:       completed
создана:      2026-11-08 15:57:52
изменена:     2026-11-08 15:57:52
попыток:      1
```

## 4. Асинхронный режим (отдельный терминал)

```console
# терминал 1
$ ma.exe load weekly.ogg --user alice --no-wait
встреча создана: 01a1bb3d-04f5-7ac6-a2af-077dd1e9309a
обработка пойдёт в режиме serve; статус: meeting-assistant status ... --user alice

# терминал 2
$ ma.exe serve
обработчик запущен, остановите по Ctrl+C

# терминал 3
$ ma.exe status 01a1bb3d-04f5-7ac6-a2af-077dd1e9309a --user alice
статус: completed
```

Что сказать: `serve` при старте возвращает в очередь задачи, прерванные прошлым
запуском — можно показать, убив процесс во время обработки.

## 5. Транскрипция и выжимка

```console
$ ma.exe get 01a1bb3c-... --user alice
Коллеги, начнём. Обсуждаем итоги спринта и планы на следующий.
По задачам: интеграция с сервисом распознавания готова, остались тесты на отмену по таймауту.
...

$ ma.exe summary 01a1bb3c-... --user alice
Ключевое из встречи «sprint-review»:
- Обсуждаем итоги спринта и планы на следующий.
- По задачам: интеграция с сервисом распознавания готова, остались тесты на отмену по таймауту.
- Договорились, что релиз выйдет в пятницу, до среды нужно закрыть код-ревью.
- Мария подготовит инструкцию для новых сотрудников и выложит её в общую базу знаний.
```

## 6. Список и поиск

```console
$ ma.exe list --user alice
ID                                    СОЗДАНА              СТАТУС     ОПИСАНИЕ
01a1bb3c-9561-7bdd-96bd-3e200d99f529  2026-11-08 15:57:52  completed  Ключевое из встречи «sprint-review»:…

$ ma.exe find "релиз" --user alice
ID                                    СОЗДАНА              СТАТУС     ФРАГМЕНТ
01a1bb3c-9561-7bdd-96bd-3e200d99f529  2026-11-08 15:57:52  completed  …Договорились, что <<релиз>> выйдет в пятницу…
```

Что сказать: основной путь — полнотекстовый поиск по GIN-индексу с подсветкой,
`ts_rank` в сортировке; если слово неполное («рели»), включается поиск по подстроке.

## 7. Вопрос по материалам

```console
$ ma.exe chat "Когда релиз?" -m 01a1bb3c-... --user alice
По материалам встречи: Договорились, что релиз выйдет в пятницу, до среды нужно закрыть код-ревью.
```

Что сказать: в контекст уходят транскрипция и выжимка, вопрос и ответ сохраняются
в `qa_history`.

## 8. Обработка ошибки и повтор

```console
$ ma.exe load fail-meeting.ogg --user alice
встреча создана: 01a1bb43-0b19-7988-b87e-88178ff010c6
статус: failed
ошибка: внешний сервис недоступен

$ ma.exe status 01a1bb43-... --user alice
статус:       failed
попыток:      1
ошибка:       внешний сервис недоступен

$ ma.exe retry 01a1bb43-... --user alice
встреча поставлена на повтор: 01a1bb43-...
статус: failed

$ ma.exe status 01a1bb43-... --user alice
попыток:      2
```

Что сказать: тестовый speech-клиент детерминированно падает на файлах с `fail`
в имени — так сценарий ошибки воспроизводим без реального сервиса. Повтор
разрешён только для `failed` и `created`, успешную обработку перезапустить нельзя.

## 9. Разграничение доступа

```console
$ ma.exe list --user bob
встреч пока нет: загрузите файл командой load <path>

$ ma.exe get 01a1bb3c-... --user bob
ошибка: не найдено: встреча
```

Что сказать: фильтр по `user_id` стоит в SQL, а чужой идентификатор неотличим от
несуществующего — существование встречи не подтверждается.

## 10. Статистика и удаление

```console
$ ma.exe stats --user alice
СТАТУС     КОЛИЧЕСТВО
---------  ----------
completed  2
failed     1

всего встреч:          3
среднее время:         8ms
вопросов по встречам:  1

$ ma.exe delete 01a1bb43-... --user alice
встреча удалена: 01a1bb43-0b19-7988-b87e-88178ff010c6
```

Что сказать: связанные строки удаляются каскадом на уровне схемы, `stats`
считает агрегаты в базе.

## 11. Тесты и конкурентность

```console
$ go test -race ./...
$ TEST_DATABASE_URL='postgres://meeting:meeting@localhost:5432/meeting?sslmode=disable' go test -race -run Integration ./...
$ go test -cover ./...
```

Что показать: `internal/worker` покрыт на 88% и проверяется `goleak` — тест падает,
если после прогона остались горутины. Отдельные тесты: лимит одновременных
обработок, отмена по таймауту, остановка посреди задачи.
